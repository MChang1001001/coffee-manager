# Coffee Manager v0.3 本地版 Release Notes

## 版本定位

v0.3 本地版是 v3 阶段总收口版本，继续定位为本地个人使用：本地 MySQL、本地 Spring Boot、本地 Vite、本地 uploads 目录、本地 exe 启动器和手动 SQL 管理。当前不包含正式登录、Docker / 上线部署、推荐算法或完整桌面应用壳。

## 已完成能力

1. `review_count` / `overall_rating` / `brew_count` 聚合回写一期：review / brew 新增、编辑、删除后回写 Coffee 聚合字段。
2. 饮用状态筛选一期：Coffee 分页列表支持 `drinkStatus`，可与 keyword / roastLevel / processMethod / origin 组合筛选。
3. 本地 smoke 残留清理工具一期：`scripts\clean-smoke-data.mjs` 支持 dry-run 预览和显式 execute 清理。
4. 枚举值 / 常用选项体系一期：`GET /api/enums/coffee` 返回 roastLevels / processMethods / origins / varieties。
5. `variety` 豆种字段：Coffee 新增、编辑、列表、详情和本地 smoke 均已覆盖。
6. 中文错误文案与提示体验统一一期：主要校验、上传、资源不存在和网络异常提示已中文化。

## 手动 SQL 说明

当前仍不引入 migration 工具，旧库变更继续通过手动 SQL 管理。执行 SQL 前建议先备份本地 `coffee_manager` 库。

旧库如果没有 `variety` 字段，需要手动执行：

```sql
ALTER TABLE coffee_beans
  ADD COLUMN variety varchar(128) null comment '品种' AFTER farm;
```

如果历史 `review_count` / `overall_rating` / `brew_count` 与现有 review / brew 数据不一致，可手动执行：

```powershell
Get-Content -Raw -Encoding UTF8 backend\src\main\resources\db\refresh_coffee_aggregates.sql | mysql -uroot -p123456 --default-character-set=utf8mb4
```

该历史修复 SQL 只修复已有聚合缓存字段，不创建表、不修改表结构。

## 脚本说明

本地烟测：

```powershell
node scripts\local-smoke.mjs
```

本地清理工具：

```powershell
node scripts\clean-smoke-data.mjs
node scripts\clean-smoke-data.mjs --dry-run
node scripts\clean-smoke-data.mjs --execute
```

`clean-smoke-data.mjs` 默认就是 dry-run，只预览不删除。只有 `--execute` 会物理清理明确属于 `[SMOKE_TEST]` 的 coffee 记录、关联 review / brew 记录，以及这些 smoke coffee 数据库记录明确引用的上传封面文件。无法证明归属的 uploads 文件会跳过。

## 当前已接受风险

1. 枚举选项一期写在后端静态代码里，没有字典表和后台管理。
2. 枚举接口走现有 JWT 认证体系。
3. 饮用状态基于数据库 `CURRENT_DATE`，依赖本地 MySQL / 后端时区一致性。
4. 历史聚合字段一致性依赖手动 SQL。
5. clean 脚本会跳过无法证明归属的 uploads 文件。
6. 后端中文 message 需要重启服务后生效。
7. 前端封面大小限制当前按后端 5MB 配置同步写死。
8. 当前仍是本地个人使用定位。
